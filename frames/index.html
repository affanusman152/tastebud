Frames: small pieces of interface, made with care

Each frame is a common UI moment done properly: every state, readable, reachable by keyboard and big enough to tap. They all read their colors, sizes and spacing from tokens.css, and their styles live in frames.css. Copy them, then make them yours.

Buttons with every state

Use for actions. Links go somewhere; buttons do something.

Why this works

  • One filled button per view, so the main action is obvious.
  • Labels are verbs plus objects: "Book wheel 2", not "Submit".
  • Every button is at least 44px tall and shows a focus ring.
  • Loading keeps the button's place and says what is happening.
  • "Disabled" uses aria-disabled so it can still explain itself on focus.

The generic version

  • Three equally loud buttons side by side.
  • "Click here", "Submit", "Learn more" with no object.
  • Pill buttons with a gradient and no visible focus.
  • A greyed-out button with no hint about why.

Text field with an error

Use for any input. The error below is what people see after a wrong entry.

We text and email 2 hours before your slot. Add an @ and a domain, like amara@riversideclay.org

Why this works

  • A real label above the field, so it stays visible while typing.
  • The hint answers the question before it is asked.
  • The error says how to fix it, with an example, and is linked to the field for screen readers.
  • Error is shown by color, an icon and text, never color alone.

The generic version

  • Placeholder text as the only label; it vanishes when you type.
  • "Invalid input" in red with no hint about what is valid.
  • A red border as the only sign that something went wrong.

Empty state

Use when a list has nothing in it yet. It is the first screen many people see.

No bookings this week

Wheels 2 and 3 are free on Thursday evening. Booked slots show up here with their times.

Why this works

  • Says what will appear here, so people learn the screen.
  • Offers the one action that fills it.
  • Uses real, useful information instead of a mood.

The generic version

  • A big illustration and "Nothing here yet!" with no next step.
  • A blank white area that looks like a bug.

Loading skeleton

Use while content is on its way, for anything over about half a second.

Loading this week's bookings

Why this works

  • Shows the shape of what is coming, so the page does not jump.
  • Announces "Loading this week's bookings" to screen readers.
  • The pulse stops for people who turn on reduced motion.

The generic version

  • A spinner in the middle of an empty page.
  • Shimmer effects that never stop and say nothing.

Error message

Use when something failed and the person needs to act.

Your booking for wheel 2 was not saved

Kiln could not reach the studio's calendar. Your other bookings are safe. Try again; if it fails twice, the studio desk can book it for you.

Call the studio desk

Why this works

  • The heading says exactly what failed.
  • It says what still works, which lowers panic.
  • It gives a next step and a fallback. No apology, no blame.

The generic version

  • "Oops! Something went wrong." with a sad emoji.
  • An error code with no explanation.
  • A toast that disappears before anyone reads it.

Navigation bar

Use at the top of every page. Press Tab inside the frame to find the skip link.

Skip to main content Kiln
  • This week
  • Firings
  • Members
  • Settings

Why this works

  • A skip link lets keyboard users jump past the menu.
  • The current page is marked visually and with aria-current.
  • Links are 44px tall even though the text is small.
  • On phones the links wrap instead of hiding.

The generic version

  • Seven links in light grey, 13px, no current-page marker.
  • A hamburger menu on a desktop screen with plenty of room.

Data table

Use when people compare items across the same columns. Cards hide that comparison.

Why this works

  • A real <table> with a caption and header cells, so screen readers announce each column.
  • Numbers use tabular figures so they line up.
  • Status is a word, with color as a bonus.

The generic version

  • A grid of identical cards, one per row of data.
  • Green and red dots as the only status signal.

Ranked features

Use instead of the three-identical-cards row on a landing page.

The booking sheet, but it updates itself

One row per wheel, one column per hour, like the paper sheet on the studio door. Tap a free slot to book it.

Kiln firings

Add pieces to the next firing and get a message when they're out.

Fair limits

A weekly cap per member so the regulars don't take every Saturday.

Why this works

  • The most important idea gets the most space.
  • Each line is specific to this product; none of it could describe another app.

The generic version

  • Icon, title, blurb, three times, all equal.
  • Titles like "Lightning fast", "Secure", "Easy to use".

Confirmation message

Use right after an action succeeds, so people know it worked.

Wheel 2 booked for Thursday, 6 to 8 p.m.

Why this works

  • Uses the same verb as the button ("Book" becomes "booked").
  • Repeats the details, so mistakes are caught right away.
  • Offers Undo instead of an "Are you sure?" dialog up front.
  • role="status" announces it without stealing focus.

The generic version

  • "Success!" with a confetti animation.
  • A message that vanishes in two seconds.
